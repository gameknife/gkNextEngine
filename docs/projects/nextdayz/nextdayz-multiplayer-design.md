# NextDayz 多人联机：Master 调度 + 关卡 DS

本文是 NextDayz 多人联机的设计契约与 MVP 执行顺序。目标形态接近 DayZ：每张地图由独立的
专用服务器（DS）承载，玩家进入后是互相独立的探索者；DS 可配置是否允许玩家互伤；一个总服务
（Master）负责账号档案、DS 舰队与把玩家派遣到具体关卡 DS。

单人模式保留：单人 = 本地运行同一份权威模拟、只有一名玩家、不走网络。只维护一套玩法逻辑。

## 1. 已定决策（2026-11-09）

| 议题 | 决定 | 理由 |
| --- | --- | --- |
| DS 形态 | MVP 复用现有引擎 + `--dedicated`（隐藏窗口 / headless surface，跳过渲染、UI、音频），仍需 Vulkan 设备 | `Assets::Scene` 与 Vulkan 强耦合，无 GPU DS 是引擎级改造，放到 MVP 之后 |
| 移动权威 | 客户端移动 + 服务端校验（速度、穿墙、翻越形状） | 3C 有翻越/攀爬与 Jolt 角色控制器，完整预测回滚成本过高；射击、伤害、库存仍由服务端裁决 |
| Master | Go 服务 + SQLite | 仓库已有 Go 工具链（gnb）；SQLite 事务承载原子检查点 |
| 单人模式 | 保留，重构为本地模拟 | 避免两套玩法逻辑分叉 |
| 分片 | 一张地图一个 DS（地图即分片） | MVP 不做同图多实例 |
| 仓库归属 | 账号级，由 Master 持有，所有地图共用；与单人存档完全分开 | 防刷物品需要单一权威 |
| 玩家标识 | 不显示头顶名字 | DayZ 风格 |
| 传输 | ENet，封装为 `src/Modules/NextNet` | 轻量、多通道、全平台；不进 Engine core |

## 2. 进程与权威

```
 客户端 NextDayz.exe
   │ ① HTTP：登录 / 档案 / 请求出击         ┌─────────────────────────┐
   ├────────────────────────────────────────►  Master（调度 + Hive）    │
   │ ② 票据 + DS 地址                       │  账号·档案(SQLite)·地图注册│
   │◄────────────────────────────────────────  DS 舰队·派遣·签票        │
   │ ③ UDP(ENet) + 票据                     └──────────▲──────────────┘
   ▼                                                   │ 注册/心跳/角色签出/原子存档
 关卡 DS：NextDayz.exe --dedicated --map <id> ─────────┘
```

| 进程 | 权威范围 |
| --- | --- |
| Master | 账号、角色档案（仓库、黄金、在外角色）、地图注册、DS 拉起/回收、派遣、票据 |
| 关卡 DS | 一张地图的世界：感染者、物资、时间天气、直升机、伤害结算、玩家库存与生存数值 |
| 客户端 | 输入、相机、本地移动、全部表现（rig、视图模型、音效、特效、HUD） |

## 3. 核心契约

1. **服务端权威**：伤害、库存、拾取、物品使用、生存数值、死亡、撤离由 DS 结算；客户端只发意图。
2. **物品单一归属**：任意时刻一件物品只属于 {Master 仓库, 签出到某 DS 的角色, 某 DS 的世界} 之一。
   DS 检查点 = 世界 + 本 DS 全部在外角色的**一次原子提交**，带单调递增序号；Master 拒绝过期序号。
   DS 崩溃时世界与角色回滚到同一检查点，不产生复制物品。
3. **角色租约**：出击时 Master 把角色签出给 DS（`sortieId` + 序号）；只有持租约的 DS 能写回；
   撤离、死亡、断线超时归还。
4. **互伤**：DS 启动参数 `--pvp on|off`，Master 派遣时下发，管理接口可运行时切换；所有伤害经过
   唯一的 `DamageRules` 判定点。
5. **模拟层边界**：`Sim/` 不得引用渲染、UI、音频与输入；表现层只读模拟状态和事件。以后换无 GPU
   DS 时只改引擎。

## 4. 网络参数

- DS 固定 30 Hz 模拟，20 Hz 快照；客户端 100 ms 插值缓冲。
- 命中判定在服务端，回溯 ≤250 ms 的命中盒历史（延迟补偿）。
- 兴趣管理按距离：玩家/感染者按半径过滤；物资点状态加入时全量、之后增量广播。
- 协议二进制，消息表集中在一个 def 头文件（X-macro）；握手校验协议版本与内容哈希（地图版本、物品表）。
- 断线：身体原地保留 N 秒（防战斗下线），之后存档移除；窗口内重连原地续接。

## 5. 里程碑

依赖：M1 ∥ M2 → M3 → M4；M5 服务主体可与 M4 并行，联调在 M4 之后；M6 贯穿。

### M1 模拟层拆分（不联网）

- GameInstance 拆为 `Sim/`（多玩家权威世界）与 `Client/`（输入、相机、HUD、音效、特效、rig）。
- PlayerController 拆运动体与相机/输入；WeaponSystem 拆武器状态/开火判定与视图模型表现。
- 多玩家化：感染者在多名玩家中选目标（**已完成第一步**：`ZombieSystem` 目标列表）；刷怪预算与
  物资补货视线判定考虑全部玩家；感染者导航从"以玩家为中心的滑动窗口"改为 DS 全图构建或按玩家簇
  多窗口（实测后定）。
- 验收：单人模式现有 `[NextDayz]` 单测与 agentscript 全过；新增进程内双玩家测试（互伤开/关、
  感染者切换目标、物品单一归属）。

### M2 NextNet 传输模块

- ENet 封装、连接生命周期、握手、通道、位序列化与量化、网络统计、链路模拟器（延迟/丢包/抖动）、
  loopback 传输。
- 验收：纯 CPU 单测；200 ms / 1% 丢包下可靠消息不丢不乱序。

### M3 DS 运行模式

- 引擎 `--dedicated`；`NextDayz --dedicated --map <id> --port <p> --pvp on|off --max-players N`。
- 固定步长、控制台日志、Ctrl+C/SIGTERM 先存档后退出、无人时降频。
- 验收：Windows/Linux 加载洛克特 30 Hz 稳定，记录空载资源占用。

### M4 复制与联机客户端（直连）

- 快照 + 增量：远端玩家（复用 PlayerRigVisual）、感染者（紧凑状态 + 事件，复用 ZombieRigVisual）、
  物资点/掉落堆、时间天气、直升机（全图共享一架，谁登机谁撤离）。
- 意图 RPC：开火（服务端回溯命中）、拾取（复用 Reserve→Commit）、使用/穿戴/丢弃/配件（复用库存事务）；
  库存只同步给本人。
- `--connect ip:port` + 开发票据。
- 验收：1 DS + 2 客户端，150 ms / 2% 丢包：互见移动动作、共同打感染者、互伤开可击杀掉落、关无伤害、
  抢同一物品只有一人得到。

### M5 Master（调度 + Hive）

- 账号：昵称 → playerId + token。档案：仓库、黄金、在外角色；安全屋操作走 Master API。
- DS 舰队：按需拉起、端口分配、注册/心跳、空闲回收、崩溃检测与租约过期。
- 派遣：请求出击 → 选有容量的 DS（无则拉起）→ HMAC 票据 → 客户端连 DS → DS 签出角色。
- 原子检查点、撤离/死亡写回；管理接口（列表、踢人、切互伤、关停）。
- 验收：登录 → 安全屋 → 出击 → 搜刮 → 撤离入库 → 再出击；强杀 DS 后回滚一致且无复制物品；
  Master 重启后在外玩家可继续。

### M6 工具、压测与文档

- `gnb mp up|down|status|bots`；轻量 bot 客户端（不渲染）；联机调试面板接入 F5 调试器；
  双客户端 agentscript；16 bot × 30 分钟浸泡测试。

**规模目标**：一台开发机 1 Master + 最多 4 DS（每图一个），每 DS 16 玩家、48 感染者。

## 6. MVP 不做

公网部署 / NAT 穿透 / 加密、真实账号与反作弊、同图多实例、载具、语音、移动端联机客户端、
无 GPU DS、完整移动预测回滚。

## 7. 直连联机原型（当前可运行）

M2/M3/M4 的第一个可玩切片：一个 NextDayz 进程当地图服务器，其余进程作为客户端直连。还没有 Master。

最快的方式是 `gnb ds`：本地起一个隐藏窗口的服务器，加载完地图后再起一个客户端连上，客户端关掉时服务器一起停止
（`--clients 2 --pvp` 两人互伤，日志在 `out/build/<preset>/ds-runs/`）。手动启动的等价命令如下。

```powershell
# 服务器（无本地玩家，隐藏窗口；UDP 27015；互伤开）
out/build/windows/bin/NextDayz.exe --hidden-window --cvar "nextdayz.net.mode server" --cvar "nextdayz.net.pvp true"
# 客户端（每开一个就是一名幸存者；跨机器时把 host 换成服务器 IP）
out/build/windows/bin/NextDayz.exe --cvar "nextdayz.net.mode client" --cvar "nextdayz.net.name alpha"
out/build/windows/bin/NextDayz.exe --cvar "nextdayz.net.mode client" --cvar "nextdayz.net.name bravo" --cvar "nextdayz.net.host 127.0.0.1"
```

| CVar | 作用 |
| --- | --- |
| `nextdayz.net.mode` | `off`（默认，单人）/ `server` / `client`，启动时生效 |
| `nextdayz.net.host` / `nextdayz.net.port` | 客户端连接地址 / 服务器监听端口（默认 27015） |
| `nextdayz.net.pvp` | 服务器：是否允许互伤；运行中在服务器控制台改也会立即通知所有客户端 |
| `nextdayz.net.name` | 客户端昵称（只出现在服务器日志） |
| `nextdayz.net.maxPlayers` | 服务器人数上限；客户端据此准备最多 4 个远端角色 |
| `nextdayz.net.kit` | 客户端出生自带 AK、60 发与背包（测试用，默认开） |

行为：
- 客户端跳过安全屋，直接出生在地图第一个安全落点，按幸存者 id 排成小圈；地图以服务器为准（不一致会自动切图）。
- 服务器运行 WorldSim：感染者只在服务器刷新、感知、追击和攻击，20 Hz 快照给客户端；客户端插值显示，
  命中盒取自本地动画，命中感染者上报服务器结算，伤害通知广播给所有人（只有射手有命中标记）。
- 客户端 30 Hz 上报位置与表现状态；远端幸存者用同一套士兵 rig 播放其移动、持枪、换弹和翻越。
- 枪声等噪声上报服务器，感染者能听到任何一名幸存者。昼夜与天气以服务器为准。
- 互伤：客户端按远端幸存者胶囊判定命中（头部 ×2、腿 ×0.6、整体 ×0.6），服务器检查开关和射手位置后
  转发给受害者；关闭时服务器丢弃。
- 左下角状态行显示在线 id、RTT、其他人数与互伤开关。
- 物资由服务器所有（协议版本 2）：
  - 客户端加载完地图后请求一次全量物资（刷新点、地图手摆物资、地面掉落堆），之后只收变化；
    服务器按全部幸存者的位置与视线补货，客户端不自行补货。
  - 拾取：客户端本地播完搜刮动作后，先确认至少有东西装得下，再向服务器请求"拿走这一处的全部"。
    服务器按到达顺序裁决（必须在可及范围内），只有第一个请求得到它；被拒的一方提示有人先拿走了。
    拿到后放进背包，装不下的作为地面掉落堆交还服务器。
  - 丢弃、调试给予溢出和联机死亡（身上全部物品）都请求服务器生成掉落堆，所有人可见可捡。
  - 联机时电台空投暂不可用；重开一局不会重置服务器的物资与时钟。
- 物品守恒（协议版本 3，`Sim/ItemLedger`）：服务器为每名幸存者记一本账，记录它所知的随身物品总数。
  - 客户端背包仍在本地操作（手感不变），有变化时最多每 0.2 秒把整个背包可靠地报给服务器，带"第几条命"。
  - 一条命的第一份报告必须是出生配置（口袋套装，服务器开 `nextdayz.net.kit` 时再加测试套装）。
  - 之后的报告不得比账上多出任何东西；允许的转换只有：用掉物品留下 `leftover`（喝完的水瓶变空瓶）、
    在井边把空瓶灌满。弹匣里的子弹算作对应弹药，装在枪上的配件算作配件物品，所以换弹和装卸配件不改变总数。
  - 拾取得到的东西记入账上；丢弃只能丢账上有的东西，然后从账上扣除。
  - 不合规的报告被拒绝，服务器把上一次认可的背包发回客户端覆盖（`InventoryFix`），手里的枪需要重新拿起。
  - 死亡与断线时，服务器按账上最后认可的背包在尸体处生成掉落堆。客户端不再自己决定掉落什么。
- 身体由服务器结算（协议版本 4）：
  - 服务器为每名幸存者运行一份 `SurvivalSystem`：生命、饥饿、口渴、寒冷（按服务器时钟与其背包保暖）、流血。
  - 感染者攻击与互伤都在服务器扣血（护甲取自服务器手里的背包），客户端只播受击反馈。
  - 吃喝、包扎、急救、止痛药、井边喝水、休息都发给服务器（`SurvivalAction`）；物品必须在账上，服务器从
    账上消耗并结算效果。客户端照常本地播放并立即显示，随后以服务器为准。
  - 服务器每 0.25 秒（受伤、用物品时立即）把身体状态发给本人（`SurvivalState`）；客户端不再自己跑代谢。
  - 死亡由服务器判定：血量归零时服务器留下尸体、通知客户端，客户端进入死亡界面，重开即新的一条命。
  - 互相可见的服装：位置上报附带已穿戴的衣物，远端角色显示相同服装。
  - 移动校验（只检测不纠正）：一次上报水平移动超过 6 m 且速度超过 25 m/s 时记录警告。
  - `gnb ds --cheats` 让服务器接受客户端测试钩子的自伤（`nextdayz.net.cheats`），只用于自动化测试。
- 专用服务器不渲染：引擎 `--dedicated`（`--dedicated-tick-rate`，默认 30）只跑游戏逻辑，不绘制、不呈现、
  不做管线预热；后台任务（场景加载）照常在主线程完成。隐含隐藏窗口、关闭 Streamline/FidelityFX 与硬件光追。
  仍需要 Vulkan 设备来装场景网格（CPU 射线与物理用的数据由此构建）。`gnb ds` 默认用它起服务器，
  `--show-server` 才画服务器窗口。实测空载约占 0.11 个 CPU 核。
- 按距离同步：每个客户端的快照只含 500 m 内的其他幸存者和 250 m 内的感染者；离开范围的在客户端消失。
- 延迟补偿的命中校验：服务器每个 tick 记下所有感染者与幸存者的位置（保留 1 秒）。客户端报告的命中
  （打感染者、互伤）按"射手看到的那一刻"（当前时间减去半个 RTT 与 0.12 s 插值延迟，前后各 0.15 s）
  回溯：命中点必须落在目标当时身体轴线 1.05 m 以内，且射手到命中点之间没有被场景挡住，否则拒绝。

自动冒烟：先 `gnb ds --clients 0` 起服务器，再同时运行两组 agentscript：
- `nextdayz-net-bravo` 与 `nextdayz-net-alpha`（服务器需 `--pvp`）：bravo 能看到 alpha 和感染者，并在 alpha 的
  互伤命中后掉血。
- `nextdayz-net-loot-bravo` 与 `nextdayz-net-loot-alpha`：alpha 拿到安全落点旁最近的物资；bravo 随后对同一处
  发起请求被服务器拒绝，并看到它已消失；bravo 能看到 alpha 丢下的绷带。
- `nextdayz-net-ledger`（单客户端，服务器需 `--cheats`）：出生套装被接受；本地凭空多出的 5 个绷带被服务器
  收回；真实拾取与丢弃被接受；死亡后由服务器留下尸体掉落堆。
- `nextdayz-net-hits`（单客户端）：报在感染者旁 5 m 的命中被服务器拒绝，打在其胸口的命中被接受。
- `nextdayz-net-survival`（单客户端，服务器需 `--cheats`）：服务器扣的血到达客户端；客户端本地改的饥饿值被
  服务器改回；致命伤由服务器判定死亡并留下尸体。

已知限制（下一步）：子弹消耗不做逐发核对（只保证不凭空增加）；移动只检测不纠正；命中由客户端发现、服务器
回溯校验（不是服务器自行重放射线）；服务器仍需要 Vulkan 设备；没有 Master、账号和存档（重启即重置）；
压测工具（机器人客户端、延迟/丢包模拟、联机调试面板）待做。

  `targetId`，伤害请求带受害者 id，挤开逻辑对全部玩家生效；单人路径以 id 1 包装调用。
